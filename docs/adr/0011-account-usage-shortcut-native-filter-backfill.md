# ADR 0011: 账号使用记录入口采用原生筛选回填而非请求改写

状态：accepted

账号管理页需要为每个账号提供跳转到管理端使用记录（`/admin/usage`）并自动按该账号筛选的入口。上游使用记录页已支持 `?user_id=` 深链，但不识别 `account_id`；账户筛选是一个“按名称搜索 + 点击下拉项”的控件，只有点击下拉项后才会写入页面的 `filters.account_id`。我们决定用 `?account_id=<id>` 作为深链种子，由插件按 ID 取回账号名并模拟原生筛选：填入账户搜索框、点击对应 `#id` 下拉项；不做请求层的 `account_id` 注入。

原因是请求层注入只能改变网络请求，无法写入 Vue 的筛选状态。`UsageCleanupDialog` 会用 `filters.account_id` 构造清理任务范围，导出与统计也依赖同一份状态；若只在网络层过滤，页面看起来已按账号筛选，但“清理使用记录”会清掉所有账号的数据，造成危险的筛选范围不一致。原生回填让明细、统计、导出、清理都使用同一份真实筛选状态。

## Considered Options

- **请求改写**（拒绝）：首屏无闪烁、能绕过账户搜索前 20 条的限制，但清理任务的 POST body 不受 URL 改写影响，存在破坏性的范围不一致。
- **混合方案**（拒绝）：请求改写保证首屏，同时原生回填；兜底期间仍需禁用清理并处理用户手动操作的竞争，复杂度和风险不值得。
- **只带 URL 不做回填**（拒绝）：上游不识别 `account_id`，页面不会实际筛选。

## Consequences

- 首屏可能短暂显示未筛选数据，随后回填并刷新。
- 目标账号不在账户搜索前 20 条、账号名读取失败或 DOM 结构变化时，需要用户手动选择；插件显示常驻提示条（重试/关闭）。
- URL 参数保留为刷新种子；用户手动改选后本页生效，刷新会重新应用最初点击的账号，与上游 `?user_id=` 深链行为一致。
