# ADR 0008: 用户脚本全自动化分发、自动更新元数据注入与“4+1”工程化标准

此前仓库内的部分脚本存在分发割裂：`a6api`、`sub2api`、`linuxdo` 具备独立构建与发布流，而 `cursor` 仍为纯静态手工安装脚本，且缺少根级统一索引文档；CI 工作流向 `build` 分支发布时硬编码脚本名称，存在脚本相互覆盖的风险。

我们决定确立仓库级统一的“用户脚本分发标准”：
1. **自动更新元数据注入**：所有脚本源码不写死更新源，统一由 `build-userscript.mjs` 在 CI 中注入 `@updateURL` 与 `@downloadURL`（双通道支持 GitHub Pages 与 GitHub Raw），版本号统一采用 `<major>.<minor>.${GITHUB_RUN_NUMBER}` 单调递增策略，确保油猴能够无感静默自动更新；
2. **安全隔离发布机制**：所有脚本的 CI 流水线采用通配保留模式（`cp *.user.js "$publish_dir/"`），消除多脚本并发或先后发布时的覆盖冲突，最终统一驱动 GitHub Pages 部署；
3. **“4+1”新脚本准入规范**：所有存量及未来新增脚本必须严格满足独立目录内的 4 个标准文件（源码、构建脚本、单测、独立文档）与根目录 1 个 CI 工作流；
4. **根索引门户**：在仓库根目录建立统一的 `README.md`，提供全量脚本一键安装索引表、油猴自动更新配置指南、本地热载开发指南以及新脚本接入 SOP。
